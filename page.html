Use Token Meter effectively

A practical review loop for controlling spend, context pressure, and unnecessary capability loading.

Recommended workflow

1

Start with the current summary

Check estimated spend, context use, cache behavior, and the latest execution before deciding whether the session needs intervention.

2

Inspect execution spikes

Use Activity to find the execution where tokens, cost, context, or tool calls changed sharply, then inspect the prompt and result around that point.

3

Act on evidence, not one-off noise

Use Insights for immediate issues, then Global and Daily to confirm whether the pattern repeats across logs or days.

4

Review capability loading

Open Tools & Skills, review exact runtime-qualified controls, and disable only packs or MCP servers that remain unused across scanned logs.

5

Close with the daily summary

Compare today with recent days, note the dominant runtime and highest-cost logs, and verify whether flagged tool results are trending down.

Ask from your agent

After connecting Token Meter in Settings, ask naturally. The agent receives a bounded verdict and a link back to the evidence.
Should I keep this run going?Checks current cost, context pressure, tool-result volume, and the strongest action.
Why was the last phase expensive?Drills into a retained execution without returning prompts, arguments, or result content.
What should I change before the next phase?Combines current-run evidence with one practical recommendation.
