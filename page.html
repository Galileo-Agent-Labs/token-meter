Use Token Meter effectively

A practical review loop for controlling spend, wait time, context pressure, and unnecessary capability loading.

Recommended workflow

1

Start with the current summary

Check estimated spend, wait time, context use, cache behavior, and the latest execution before deciding whether the session needs intervention.

2

Inspect execution spikes

Use Activity to find the execution where tokens, cost, context, or tool calls changed sharply, then inspect the prompt and result around that point.

3

Act on evidence, not one-off noise

Use Insights for immediate issues, then Global and Daily to confirm whether the pattern repeats across logs or days.

4

Review capability loading

Open Tools, review MCP usage as read-only evidence, and disable only user-installed skill packs that remain unused across scanned logs.

5

Close with the daily summary

Compare today with recent days, note the dominant runtime and highest-cost logs, and capture any follow-up for the next run.

Compare model speed without fooling yourself

Context size, output length, tools, cache behavior, and runtime all affect how long a turn takes. Use the Models view in this order.
Step 1

Select two model runtimes

Compare exact histories such as Opus · Claude-3P and GPT · Codex. Do not pool the same model across different runtimes.

Step 2

Read matched pace first

It pairs completed turns with similar context, input, output, cache share, model-call count, tool shape, and recency. Cursor is withheld because its input and output values are local proxies, not provider-reported tokens.

Step 3

Check coverage and uncertainty

Use the pair count, smaller-history coverage, and 95% confidence interval. If the interval crosses 1.00, read the result as approximately the same.

Step 4

Treat tok/s as diagnostic

Observed output pace describes token generation in timed samples. Different TTFT evidence and sparse coverage can make it misleading across runtimes.

What matching cannot prove: two turns with similar measurable workload can still differ in semantic difficulty. Matched pace is observational evidence, not a controlled benchmark or a quality score. When there are fewer than 20 matched pairs or less than 30% coverage, Token Meter shows no verdict.

Ask from your agent

After connecting Token Meter in Settings, ask naturally. The agent receives a bounded verdict and a link back to the evidence.
Should I keep this run going?Checks current cost, context pressure, tool-result volume, and the strongest action.
Why was the last phase expensive?Drills into a retained execution without returning prompts, arguments, or result content.
What should I change before the next phase?Combines current-run evidence with one practical recommendation.
